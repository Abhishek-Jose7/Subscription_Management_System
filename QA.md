# Quality Assurance & Traceability Matrix (QA.md)

This document maps all real-world problem statement scenes to implemented features and verified acceptance criteria (PRD Section 13).

| Scene | PRD Features | Implementation Route / File | Acceptance Criteria & Verified Behavior |
|---|---|---|---|
| **New Customer Signs Up** | Public signup, unique email, D1 password policy, reset flow, customer shell, RBAC | `/signup`<br>`src/lib/auth.ts`<br>`/api/auth/signup` | **Verified:** Password requires min 9 chars (>8), >=1 upper, >=1 lower, >=1 special with live ticking green checklist. Emails normalized and unique. Creates customer user + customer shell; auto-logs in. Non-admin staff cannot invite/create staff (403). |
| **Launching a New Plan** | Products, variants (attribute -> values), plans, D14 lifecycle flags | `/api/products`<br>`/api/plans`<br>`src/app/app/page.tsx` | **Verified:** Base ₹1,000 + Brand: Odoo (+560) snapshots to ₹1,560. Plans enforce `auto_close_on_end`, `allow_early_close`, `allow_pause`, `allow_renew`. Enforced on API & UI. |
| **Quote -> Subscription** | Quotation templates, gapless numbering, state machine stepper | `/api/quotation-templates`<br>`src/lib/subscriptions/state-machine.ts`<br>`src/components/ui/StateStepper.tsx` | **Verified:** Templates pre-fill lines with validity days. Stepper renders `Draft -> Quotation -> Confirmed -> Active -> Closed`. Illegal jumps return 409 with allowed transitions. `SUB/YYYY/000000` assigned on creation. |
| **Billing Day** | Automated billing engine, idempotency, taxes, invoice lifecycle | `src/lib/billing/engine.ts`<br>`/api/billing/run`<br>`src/lib/billing/tax.ts` | **Verified:** Run billing creates invoices for due periods. | **Customer Asks for a Better Price** | Discount engine, dynamic eligibility, usage limits, redemptions | `src/lib/billing/discount.ts`<br>`/api/discounts`<br>`src/components/ui/ExplainPriceModal.tsx` | **Verified:** "10% on >=10 seats, limit 3" applies automatically on invoice generation without manual intervention. Stops when exhausted or expired. Staff creating rule gets 403. "Why this amount?" modal provides full waterfall breakdown. |
| **Money Comes In** | Payments, partials, derived overdue, portal pay, voiding | `src/lib/payments/engine.ts`<br>`/api/payments`<br>`/api/payments/[id]/void` | **Verified:** UPI and cash payments recorded with idempotency keys. Overdue and Partially Paid are derived from facts, never stored. Voiding a payment re-opens invoice balance and state. |
| **Finance Cockpit** | Real-time KPIs, MRR movement waterfall, Aging buckets | `/api/reports/cockpit`<br>`/api/reports/mrr-waterfall`<br>`/app` | **Verified:** MRR, ARR, Invoiced, Cash Collected, and Overdue AR calculate in milliseconds. Waterfall tracks New, Expansion, Contraction, and Churn from `mrr_events`. |
| **Ledger Health** | Live SQL consistency checks | `src/lib/reports/ledger-health.ts`<br>`/api/reports/ledger-health` | **Verified:** 6 SQL integrity checks: 0 duplicate periods, exact line sum reconciliation to the paisa, payment ledger matching, status matching facts, discount limits intact. All green! |
| **Virtual Clock** | Time travel simulation | `src/lib/clock.ts`<br>`/api/clock`<br>`src/components/ui/VirtualClockBanner.tsx` | **Verified:** `+1 Day`, `+1 Month`, `Reset` buttons allow live time simulation. Triggers daily billing and reflects renewals and aging immediately. |
